## 保存和生效

1. 页面先展示 **已保存配置** 与 **运行中配置**。两者不一致时显示“待生效”，避免误以为已切换。
2. 点击“测试并保存”时，服务端对主模型和每个备用模型发短文本流式测试；要求有正文并正常结束，不能只把 HTTP 200 当成功。测试结果展示耗时和失败原因。
3. 主模型测试通过后，服务端原子保存一个模型策略文件，记录主模型、按序备用模型、逐项测试结果、超时与版本号；测试失败的备用模型仍保留在列表并标出原因；不保存或返回 API 密钥。
4. 对话请求统一经过支持热加载策略的本地模型代理。代理每轮记录 **请求模型** 与 **实际响应模型**，识别空流、上游错误和超时，再按顺序尝试备用模型。健康与冷却状态可在页面查看。
5. 将主模型应用到 DSH 新会话默认值，并通过 `session/selectModel` 更新现有 QQ 会话的下次使用模型。正在生成的回合不强行改写；页面逐项显示应用结果。任一步失败时恢复上一版策略，并标明未生效的会话。
6. 保存配置以后应热生效，不要求每次重启机器人。首次启用统一代理时，需完成一次服务切换和端到端验证。

## 后端接口建议

由现有 18902 本机管理服务提供同源接口，避免页面跨端口直连代理：

| 接口 | 用途 |
| --- | --- |
| `GET /api/models/status` | 已保存配置、运行中配置、默认模型、最近实际模型、代理健康、失败摘要 |
| `GET /api/models/catalog` | 上游模型目录及能力，标记费用未知项 |
| `POST /api/models/test` | 测试指定模型的完整流式回复，不改变线上配置 |
| `PUT /api/models/policy` | 带版本号保存并应用主模型、备用顺序和超时；返回逐项结果 |

写接口沿用运行设置页的本机访问、Origin 校验、请求大小限制和串行保存机制。模型策略文件采用临时文件加原子重命名，保存前保留上一版供回滚。密钥继续由现有密钥页面管理，模型页面只显示“凭据可用/不可用”，不显示密钥值。

## 验收标准

- 打开页面即可分清当前默认模型、上一轮实际响应模型和备用链是否生效。
- 选一个可用免费模型并保存后，新会话与现有 QQ 会话的下一轮使用新主模型；无需手改 YAML 或重启。
- 主模型返回空流、502 或超时时，请求按页面顺序切到备用模型，页面记录实际命中的模型。
- 所有候选失败时，页面显示具体故障和冷却时间；不把“HTTP 200 但没有正文”显示为成功。
- 错误模型 ID、重复备用模型、并发覆盖、主模型测试失败均不能破坏上一版可用配置；备用模型测试失败时保留条目并显示结果。
